## MODELS BASE DE DADES

### Model MembreFamilia (ACTUALITZAT)
```python
class MembreFamilia(db.Model):
    # Camps bàsics
    id, usuari_id (nullable=True), espai_familiar_id
    rol, data_adhesio
    
    # Dades personals
    nom, primer_cognom, segon_cognom
    data_naixement, municipi_naixement, regio_naixement, pais_naixement
    data_defuncio, municipi_defuncio, regio_defuncio, pais_defuncio
    municipi_actual, regio_actual, pais_actual
    biografia
    
    # RELACIONS FAMILIARS (NOU)
    pare_id, mare_id
    
    # Relacions
    usuari → Usuari
    espai_familiar → EspaiFamiliar
    pare → MembreFamilia (self-referential)
    mare → MembreFamilia (self-referential)
    fills_com_pare → [MembreFamilia] (backref)
    fills_com_mare → [MembreFamilia] (backref)
    documents → [DocumentMembreFamilia]
    matrimonis_com_1 → [Matrimoni] (backref)
    matrimonis_com_2 → [Matrimoni] (backref)
```

## SISTEMA DE RELACIONS FAMILIARS

### Com funciona:

**Relacions directes (BD):**
- Pare: `membre.pare_id` → Apunta a un altre MembreFamilia
- Mare: `membre.mare_id` → Apunta a un altre MembreFamilia
- Matrimonis: Taula separada `Matrimoni` amb membre_1_id i membre_2_id

**Relacions calculades:**
- **Germans:** Si dues persones tenen el mateix `pare_id` o `mare_id`
- **Fills:** Backref automàtic `pare.fills_com_pare` i `mare.fills_com_mare`

**Flux afegir relació:**
1. Usuario clica "Afegir Pare" des de gestió relacions
2. URL: `/familia/membre/afegir/5?relacio=pare&membre_id=12`
3. Formulari normal d'afegir membre amb camps ocults
4. Al guardar: `membre_12.pare_id = nou_membre.id`
5. Redirigeix a gestió relacions
6. Automàticament es veuen les relacions actualitzades

**Filosofia:**
- Membres "flotants" permesos (sense pares)
- L'arbre es completa orgànicament amb el temps
- Flexibilitat: crear només qui interessa
- No obliga a completar tota la cadena genealògica

## NOTES TÈCNIQUES IMPORTANTS

### Gestió de Fitxers

el fitxer es gaurden a desktop/adabida/umberto

### Relacions Self-Referential
- `pare` i `mare` són relacions self-referential a MembreFamilia
- Importància del `remote_side=[id]` i `foreign_keys=[...]`
- Backrefs: `fills_com_pare` i `fills_com_mare`

### Matrimonis vs Cònjuge
- ❌ NO usar camp `conjuge_id` (massa simple)
- ✅ Usar taula `Matrimoni` (permet múltiples, dates, estats)
- Permet històric complet de matrimonis
- Suporta divorcis i viudetat

### Germans
- NO necessiten taula separada
- Es calculen automàticament amb queries
- Comparteixen mateix `pare_id` OR `mare_id`
- Futur: Distingir germans complets vs paterns/materns

- `familia_bp` → Gestió espais familiars
- `membres_bp` → Gestió membres individuals
- Separació clara de responsabilitats
- Facilita manteniment i escalabilitat
